# 检查、排障与交付发布

## 依照范围验证

- 文案：对应页面内容与大小；插页检查页号/动作索引。
- 几何/计算：输入单位、参考面、逐座结果、来源、基线差异。
- 功能：真实浏览器、控制台、帧状态、相关交互及回到原状态。
- 资源：Logo中文、产品图身份、字体、相对路径与请求错误。
- 发布：准确提交、部署工作流、公网构建标记与入口。

不要为纯文字变更强制跑全站；发现具体问题再扩大检查。

## 核心工具与运行方式

Node.js入口为 scripts/cinema-tools.cjs，无外部依赖。
inspect、metrics、compare、validate-skill和selftest的用法见SKILL.md。
inspect的ready只表示当前输入够不够执行某类工作，不代表标准合格、预算真实或项目完成。
metrics不修改文件；compare不能代替检查实际HTML中的隐藏坐标覆盖。

## 排障顺序

1. 取得复现条件：网址或文件、设备、系统/浏览器、提示、加载多久、其他设备表现。
2. 检查入口与资源路径、请求错误、缓存版本和脚本异常。
3. 检查首帧状态、WebGL支持、上下文丢失、视口尺寸与相机/裁剪。
4. 检查自动动画是否继续、控件是否争夺输入、场景有没有透明/隐藏状态残留。
5. 再考虑性能、内存、GPU或浏览器版本；说明每一步的通过/失败判据。
6. 临时恢复与根因解决分别记录；不要重复已证明无效的建议。

慢加载验证超过旧固定超时时间后仍能继续首帧，同时真实错误仍显示。
不能在没有WebGL的环境用模拟成功信号冒充完整渲染。

## 浏览器验收

受影响任务按需检查：
- 桌面、手机竖屏/横屏：双入口、导航、模式、说明栏、最大化。
- 拖动、缩放、逐座选择、按钮、暂停/重播、离页/返回。
- 每只音箱完整入画，唯一集合巡回，结束全组，标注同步。
- 数值、单位、频带不换行且不溢出；正文未被裁切。
- 场景切换后尺寸、位置、方向没有变化。
- 首帧、慢加载、真实错误、不支持设备的明确回退。

不存在测试设备时使用“未测”，保留所需验证条件。

## Git与发布

先读取当前授权：新项目不得继承其他项目的发布授权。用户要求先审阅就不发布。
明确仓库、分支、子目录和公开内容。避免用户私密资料、价格协议、测量原档和凭证被意外公开。
保护工作树；不得强推、删除历史或覆盖另一项目入口。
制作可审阅结果与必要检查后执行已授权发布；不重复索取已给的授权。
保留稳定URL；重定向保留query/hash；相对资源路径在GitHub Pages子目录实际可用。
Git提交成功、Pages部署成功、公网版本正确、三维运行成功分别记录。
仅有HTTP200不足以证明后两项。

## 交付记录

用 assets/acceptance.template.md记录环境、范围、证据和未测项。
交付源码或HTML、需求完成表、变更说明、必要操作说明与已验证网址。
手机客户不应只能获得ZIP或会话临时令牌链接。
项目记忆只更新真实事实：日期、版本、决策、实现、检查、发布和剩余问题。
