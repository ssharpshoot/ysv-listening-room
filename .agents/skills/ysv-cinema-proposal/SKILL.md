# 源声视界 · 3D影院方案制作与维护

版本：1.0.0；发布日期：2026-10-07。
将客户问题、工程依据、可操作的三维展示和交付验证连接起来。按当前项目工作，避免引用其他项目的器材和尺寸。

## 1. 先确定任务与现状

1. 读取适用的父级和项目 AGENTS.md、当前 MEMORY.md、项目数据、最新入口及本次需求。存在同名文件时合并，不覆盖已有内容。
2. 判断任务：新建 / 修改 / 排障 / 发布；判断阶段：仅规划审阅 / 已授权实现。用户明确要求等待确认时，保留该边界；已授权的常规修改与检查持续完成。
3. 检查实际工具、Git分支和用户改动。缺浏览器、终端、建模或网络工具时，记录具体限制，继续不依赖它的工作；不得声称已运行或已发布。
4. 确认同一项目的最新文件与发布入口。JBL案例只在用户指定该项目或参考其流程时读取 [JBL案例](references/jbl-v13-1-case.md)，不能用案例参数填补新项目。
5. 新项目建立独立目录、项目ID和参数；已存在的工程优先局部修改，不为套用模板迁移框架。

## 2. 按任务读取资料

| 任务 | 必读资源 | 输出 |
|---|---|---|
| 新建 | [资料与项目隔离](references/intake.md)、[客户汇报](references/customer-report.md) | 缺项表、可审阅方案、确认后网页 |
| 修改 | [三维与交互](references/presentation.md)、当前项目文件 | 需求映射、范围内差异与验证 |
| 计算或选型 | [工程口径](references/engineering.md) | 输入、来源、计算结果和适用条件 |
| 排障 | [检查与发布](references/qa-release.md) | 按成本排序的检查、实际结果、恢复或根因 |
| 发布交付 | [检查与发布](references/qa-release.md) | 版本记录、源码、变更说明、部署状态和网址 |

只加载本次需要的资源。视频任务可输出与网页一致的素材交接；独立视频制作需使用相应视频技能与工具。

## 3. 准备可审阅的需求表

按“项目/页面ID、当前表现、目标、修改类别、依据、缺项、状态、验收方法”记录。先定位当前页面内容再映射页号；插页之后更新目录和索引。
将文案、技术数据、几何、交互、动画、图片和发布分开记录。状态使用：待确认、已确认、已实现、已检查、已发布、阻塞。
用户说“不能拖动”时先判断是故障还是禁止操作的明确要求。

新建项目从 assets/project-intake.md 和 assets/project.template.json 开始。
需要项目规则和记忆时复制 assets/AGENTS.template.md、assets/MEMORY.template.md，填实际项目字段；有旧文件则合并。
需要页面计划和验收记录时使用 assets/page-plan.template.json、assets/change-request.template.csv、assets/acceptance.template.md。
模板中的空值代表未知，示例值代表示例，不能作为工程事实。

## 4. 从客户问题组织汇报

先回答：空间怎样安排、为什么这样选产品、整体花费、各座位体验、舒适与家庭影响、日常操作、工期与验收售后。
每段建立“问题 → 设计判断 → 图形或资料依据 → 客户价值与取舍”。
用真实选型比较、计算条件和测量计划体现专业性。缺价格、候选型号资料或测量时标记待补，不编造金额、竞争产品劣势或效果保证。
客户正文口语化，首次专业术语用中文（English）；细节按需展开。保留用户已批准措辞，区分体验愿景和验收指标。

## 5. 执行修改与制作

1. 从实际生效代码入手。单文件HTML可能有后置覆盖，避免只修改最早出现的同名函数；不要打印巨大内嵌图片。
2. 保留已确认几何、声道左右和工程坐标。相机、标注、高亮不得改变音箱变换；已授权几何调整先记录前后值。
3. 按页面ID绑定场景、控件、动画和数据。离页取消旧任务，重播完整重置；手动操作接管自动镜头。
4. 把座位、视角、房间共振等场景选择靠近左侧三维；右侧集中解释。数值与单位用短块不换行，正文正常换行，手机不得横向溢出。
5. 保留真实加载错误；慢加载用进度或重试提示，真实首帧后才标就绪。使用不支持的WebGL版本时提供明确提示和可阅读方案。
6. 需要可重复计算时，使用 scripts/cinema-core.cjs 和 scripts/cinema-tools.cjs；它们只作几何/标量估算和资料检查，不提供现场EQ、逐频达标或房间实际频响结论。
7. 只有在新建页面或改版获授权时使用 assets/report-layout.css；不要在维护任务中覆盖既有品牌和布局。

## 6. 检查、交付与记忆

运行适合范围的检查：小文案检查相关页面；几何/计算检查输入与数值；功能检查真实浏览器、交互和错误；发布检查Git版本、部署状态与公网内容。
将核心工具测试与完整浏览器实机验收分开记录。缺设备的项目标记未测，不用静态检查替代渲染验证。
发布按当前用户授权执行，明确仓库、分支、路径和公开范围；不要把另一项目的授权延用到新项目。
完成后给出成果、修改摘要、检查证据、剩余问题及下一步。提供手机可直接打开的已验证网址；提交成功不等于部署成功。
更新项目 MEMORY.md 和变更记录，只写有来源的事实、决策与实际测试状态，不记录令牌或签名链接。

## 7. 工具入口

运行环境：Node.js，使用 .cjs 入口，不安装外部依赖。无Node时按 references/engineering.md 手工计算并复核，明确未运行脚本。

~~~text
node scripts/cinema-tools.cjs inspect /path/to/project.json
node scripts/cinema-tools.cjs metrics /path/to/project.json
node scripts/cinema-tools.cjs compare /path/to/baseline.json /path/to/project.json
node scripts/cinema-tools.cjs validate-skill /path/to/ysv-cinema-proposal
node scripts/cinema-tools.cjs selftest
~~~

使用技能目录的绝对路径执行上述入口，避免误在项目目录查找脚本。
inspect 返回资料错误、缺项和功能准备度；metrics 仅计算资料充分的部分；compare 检查几何变化，不自动批准变化。
validate-skill 检查技能元数据、资源引用与JSON语法；selftest 运行核心工具的确定性测试。

## 8. 完成条件

- 覆盖本次已确认要求，保留有效旧内容和用户工作。
- 数值、图片、型号、单位与信号链可追溯，未验证状态准确。
- 受影响交互和排版有范围适当的检查记录。
- 成果、版本和发布状态清楚；没有实际成片或部署时不称已交付。
